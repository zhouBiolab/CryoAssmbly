### 第 7 步审计发现的缺陷（已修复）

首次暖缓存运行（`out_warm`）显示 `hits=0, misses=3, writes=3`，库从 3 行长到 6 行 —— 同一批 TM 对被重算。
根因：`structure_fingerprint()` 把**绝对路径**编码进指纹，而同一份内容在不同运行的输出目录里路径不同
（`out_p5/…` vs `out_warm/…`）→ 键必然不同，跨运行命中率恒为 0。修复：指纹改为纯内容的
`"<size>:<sha256>"`（路径只用于进程内记忆化键），并新增单测
`test_content_only_fingerprint_enables_cross_run_reuse`。修复后重新做冷库（`out_p5b`，misses 3/writes 3/rows 3）
与暖库（`out_warm2`，**hits 4 / misses 0 / writes 0 / rows 3**）两次真实运行验证。

## 一、改了什么（接口见 `ENGINEERING_HARDENING_PLAN.md` 附录 D.3）

| 内容 | 位置 |
|---|---|
| `usalign_pair()`：跑一次 USalign 返回 `(tm, seqid)`；**超时 / 非零退出 / 解析失败 → 抛 `USalignError`（带两个输入与 stderr 摘要）**，不再返回伪 0.0；合法 `TM-score=0` 正常返回 | `core/similarity.py` |
| `TMStore`（SQLite + WAL，**只由父进程打开**）：键 = 两个结构内容 `sha256` **排序后** + USalign 指纹（路径+size+mtime_ns+内容 sha256）+ 参数 + `TM_CACHE_VERSION`；`get()` 区分"缺失"与合法 `0.0`；失败不写 | 同上 |
| 两层缓存**同键**：进程内层与 SQLite 层共用同一 `pair_key`；**关闭时两层都不用**（原先只关磁盘层、内存层仍会命中） | 同上 |
| `calculate_tm_score()` / `calculate_seqid()` **共用一次 USalign 调用与同一份缓存**（原先各跑一次） | 同上 |
| `prefill_tm_cache(pairs, context, usalign_path=None)`：worker 只跑 USalign 并把成功/失败原样带回，**父进程写入**；任一失败即抛错 | 同上 |
| 开关与路径：`RuntimeConfig.tm_cache`（`"auto"` = `$XDG_CACHE_HOME/protassem/tm.sqlite3`，未设置时 `~/.cache/protassem/tm.sqlite3`；`"off"`；显式路径）；`configure_tm_cache()` 配置变化即清内存层并重建存储；`run_pipeline` 应用并在结束时记录统计 | `runtime/config.py`、`pipeline.py` |
| worker 侧不再碰库：`homo_chain_refine._seqid_worker` 改用 `usalign_pair` | `assembly/homo_chain_refine.py` |

**不做**：未经证明的几何预筛。

## 二、契约与错误处理（单测 14 项，`tests/test_similarity_cache.py`）

| 验收项 | 结论 |
|---|---|
| 首次计算、第二次命中 | ✔ 只调用一次 USalign（假二进制计数） |
| 跨"内存层重置" | ✔ 磁盘层命中（不再调用 USalign） |
| 交换结构顺序 | ✔ 命中同一条记录 |
| 输入/二进制/参数变化 | ✔ 结构内容变化、USalign 二进制变化都会失效并重算 |
| 合法 `0.0` | ✔ 返回 0.0 **且允许缓存**（与"失败"区分） |
| 超时/非零退出/解析失败 | ✔ 抛 `USalignError`（含退出码与 stderr），**不写库**；`prefill` 同样抛错 |
| 关闭缓存 | ✔ 两层都不用：每次都真算 |
| 默认路径 | ✔ `XDG_CACHE_HOME` 优先，其次 `~/.cache` |
| TM 与 SeqID 共用一次调用 | ✔ 同一次 USalign 的两个解析结果 |

全量测试：**226 项通过**。
