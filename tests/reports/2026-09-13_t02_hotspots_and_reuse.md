# T02：固定配准热点与源侧可复用比例（实测报告）

日期：2026-09-13　代码：`feat/runtime-metrics` @ `59ac461`
输入：`tests/cases/registration_manifest.json`（1 源 7335 点 + 3 个掩码 8006/3565/1672 点，
每目标 12 对 = 6 配置 × 2 采样），**冷/暖各一次重复**（暖 = 同进程第 2 次）。
GPU：A800 **MIG 7g.80gb 切片**；显存数字是切片内进程级。

## 一、埋点与口径

- 模型内三阶段用 **CUDA event** 计时（记录时不强制同步，`flush()` 时同步一次后回放）：
  `model_backbone`、`model_transformer`、`model_lgr`。
- 服务端新增 `server_collate`（采样/降采样）、`server_neighbors`（分区）、`server_pair_info`（指纹）、
  `server_mem_peak`（显存峰值）；`server_postprocess` 只统计"变换 + overlap 计算"。
- **口径修正（本轮自查发现）**：首版 `server_postprocess` 的计时起点在 `model(...)` 之前，
  等于把 `server_forward` 也算进去（读数 14.24 s ≈ forward 11.46 + 2.8）→ 属"重叠时间相加"错误；
  已改为从模型结束处起算（修正后 2.49 s）。下表为修正后数据。
- `server_forward` 是**模型调用的主机侧 wall**，包含下面三条 CUDA 阶段；两者**不可相加**。

## 二、阶段耗时（冷/暖各 36 对，累计秒）

| 阶段 | 冷 | 暖 | 说明 |
|---|---|---|---|
| server_forward（主机 wall，含下列 CUDA 阶段） | 12.56 | 11.64 | 与 CUDA 阶段之和差 ~2.4 s = forward 内主机侧开销 |
| server_write_pred | 6.94 | **2.07** | 冷/暖差 −70%%：首写 36 个 PDB 的 I/O 预热，**不是算子收益** |
| model_lgr（假设生成/评分） | 6.92 | 7.08 | 模型内最大头（占三阶段 68%%） |
| model_backbone（两侧联合编码） | 2.80 | 2.45 | |
| server_postprocess（变换+overlap） | 2.49 | 2.54 | |
| server_neighbors（分区） | 0.88 | 0.87 | |
| model_transformer | 0.46 | 0.46 | |
| server_preprocess / collate / to_gpu | 0.25 / 0.13 / 0.03 | 同量级 | 可忽略 |

每对配准 wall（冷）合计 **36.51 s**（≈1.0 s/对）。

## 三、源侧可复用比例的**上界**

| 口径 | 冷启动占比 |
|---|---|
| 几何 + 分区（`server_collate` + `server_neighbors`）—— 无条件可缓存 | **2.8%%** |
| 加上联合编码 `model_backbone` | **10.4%%** |
| 模型三阶段合计 | 27.9%% |

**结论**：即使把源侧几何与编码全部缓存命中，本基准的收益上界约 **10%%**（其中 backbone 是两侧联合编码，
真正的"源专属"部分更小；须待 T04/T06 拆分后才能量化）。任务卡要求的"不承诺固定加速倍数"在此得到支持。

## 四、重复率与 scale 命中机会

- **源几何重复率 98.6%%**（同一源在 72 对里被重建 72 次）——缓存"可应用"，但绝对收益受第三节上界约束。
- **scale 命中机会 95.8%%**（72 对里只有 3 个不同 scale 位模式：`42b9781c` / `42bbed16` / `42ce71f1`）。
  ⚠️ 这是本基准"3 个固定目标各重复两次"的产物：真实流程里同一目标被逐步掩膜后半径改变 → scale 会变，
  生产命中率应低于此值。**T07 须按真实掩码序列复测命中率，不得直接引用 95.8%%。**

| allocated | 3746.9 |
| reserved | 4952.0 |

任务卡给 T07 的 GPU 缓存预算是 256 MiB ≈ 当前峰值的 5%% ✓ 有空间；但 MIG 切片上限本就小，需在 T03 复核。

## 六、对后续卡的指向（依实测，不预设）

1. **T03（内存与回传）**：`server_forward` 主机 wall 比 CUDA 阶段之和高 ~19%%（2.4 s/12.56 s），
   说明 forward 内主机侧（归一化、对应选择、字典组装）有可观开销；同时 `max_allocated` 4.85 GiB
   提示中间张量驻留值得整理。
2. **T08（假设评分分块）**：`model_lgr` 是模型内最大头（6.92 s，占模型 68%%）→ 分块收益最可能出现在这里。
3. **T05/T07（缓存）**：收益上界 ~10%%（源侧）与 scale 命中待实测；应先把 T03/T04/T06 的"确定性拆分"做完，
   否则缓存命中率与收益都无法归因。
4. **写盘**：`server_write_pred` 暖态 2.07 s/36 对，占每对 wall 的 5.7%%；冷态 19%% 属 I/O 预热，
   不应计入算子优化目标（若要减少，应减少预测数量或合并写盘，属独立决定）。
